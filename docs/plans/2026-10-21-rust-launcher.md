# Rust Launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `launcher-rust/`, an iced 0.14 launcher that replaces `launcher/spartanport_launcher_win.py` 2.6.0 page by page, reads and writes the same files, and ships with Rust tests that replace the Python launcher tests.

**Architecture:** One crate, `spartanport-launcher`. `src/core/` holds every file format, parser, process and network concern with no iced dependency and byte-for-byte parity tests against fixtures the Python launcher produced. `src/ui/` is an Elm application (`State`, `Message`, `update`, `view`) over that core, tested headless with `iced_test`. Until the runner sub-project exists, the game starts through `python run.py`.

**Tech Stack:** Rust stable (rustup), iced 0.14 (`wgpu`, `tiny-skia`, `image`, `canvas`, `advanced`, `tokio`), `iced_test` 0.14, `serde_json` (`preserve_order`), `indexmap`, `roxmltree`, `ureq`, `sha2`, `image`, `zip`, `rfd`, `thiserror`, `windows-sys`, `winresource`, `tempfile` (dev).

**Spec:** `docs/specs/2026-10-21-rust-launcher-design.md` (visual reference: `docs/specs/assets/rust-launcher/launcher-mockup-v13.html`). Python reference: `launcher/spartanport_launcher_win.py` at commit `541739b` (2.6.0). Read the spec before any task; read the named Python function before porting it.

## Global Constraints

- Crate at `launcher-rust/`, package `spartanport-launcher`, version `2.6.0`, cargo binary `spartanport-launcher` (packaging renames it `SpartanPort.exe` on Windows in sub-project 4).
- `src/core/**` never contains the string `iced` (a test enforces it).
- No `unwrap`/`expect` outside `#[cfg(test)]`; `clippy::unwrap_used` and `clippy::expect_used` are denied at the crate root. `unsafe` only inside `src/core/launch.rs` and `src/core/platform/windows.rs`.
- Files written must equal the Python launcher's bytes: `settings.json` is `serde_json::to_string_pretty` (2-space indent, UTF-8, no trailing newline, insertion order kept); `spartanport.ini` keeps comments and order, appends new keys, ends with `\n`; `mods.json` and `patches.json` likewise pretty with 2 spaces.
- Every write is atomic: temp file in the same folder, fsync, rename.
- Data folder: `SPARTAN_DATA_DIR`, else the executable's folder; `SPARTAN_CONFIG` overrides the ini path. Legacy config: `%APPDATA%\gow3-launcher` or `$XDG_CONFIG_HOME/gow3-launcher` (default `~/.config`).
- Languages: `en`, `ru`, `ar`, `es`, `pt`, `fr`, `de`, `it`, `pl`, `tr`, `zh`, `ja`, `ko`, `id`; English is the key, a missing entry falls back to English, `ru` comes from the inline `_('en', 'ru')` pairs.
- Palette and timings exactly as the spec section 3.3 and 4: `#0d0b0b #161212 #1d1717 #2a2222 #e6e0d8 #8a817a #a4161a #c81e25 #c9c4bd #b8862b`; splash min 800 ms, max 3000 ms; drawer 220 ms, widths 46 % and 72 %; language menu hover 450 ms, close 300 ms; log batches ≤ 250 ms; log ring 6000 lines; `close_on_play` hides after 5000 ms.
- Window minimum 1280 × 800 logical pixels; page order `home graphics performance game trophies controls mods advanced log`.
- Commit messages: Conventional Commits with this repo's capitalised type and scope, imperative, ≤ 50 characters (`Feat(Launcher): add settings parity test`). No AI attribution lines.
- Never start or stop the user's real game; integration tests use the `fake-game` binary.

## Review Focus

- A `settings.json` that is valid JSON but not an object (e.g. `[]` or `"x"`): the launcher must open with defaults and never overwrite the file until Save. Test added to Task 5.
- A `spartanport.ini` line with `=` inside a comment-less value (`extra=a=b`) and a key with surrounding spaces: `load_ini` keeps `a=b` as the value and the trimmed key; `save_ini` rewrites that line, not a new one. Test added to Task 6.
- `spartanport-gpu-capabilities --list` printing a row whose name contains a tab or a `\r`: `parse_gpu_list` keeps the row only when it still has ≥ 3 columns and a numeric index, never panics. Test added to Task 9.
- A game process that writes 10 MB without newlines, or closes stdout but keeps running: the reader thread must not block the UI, the ring buffer must stay at 6000 lines, and `GameExited` arrives after the real exit. Test added to Task 14.
- A trophies `.trp` whose entry count claims 100 000 entries in a 1 KB file: `read_trp_icons` returns what fits and never reads past the slice. Test added to Task 16.
